# Task E (bonus) — Шлях 3: набір тестів на авторизацію

**Що зробили:** Два шари перевірки, а не один.

1. **Автоматизовані тести** (`app/test/api.test.js`) — кожен маршрут, що
   торкається конкретної нотатки, має тест саме на «чужого користувача»:
   `will not read someone else's note` (GET одна нотатка), `will not archive
   someone else's note` (PATCH архів), `will not delete someone else's note`
   (DELETE). Вони входять у `npm test` і падатимуть при регресії.
2. **Ручний прохід через `curl` по живому серверу** — той самий сценарій, що
   й тести, але з реальними HTTP-запитами й видимими відповідями, плюс один
   випадок, якого автотести не покривають: спроба підмінити `user_id` у тілі
   `POST`-запиту (mass assignment).

Для проходу створили дві контрольні нотатки з відомим власником (а не
покладались на те, що засіяні id 1–3 досі існують і належать тим самим
користувачам — вони вже встигли змінитися за час ручного тестування додатку
через браузер), прогнали кожен ендпоінт від імені **не того** користувача,
після чого прибрали за собою тестові нотатки.

| Ендпоінт | Як чужий користувач | Очікувано | Фактично |
|---|---|---|---|
| `GET /api/notes` | Тарас читає свій список, поки в системі існує нотатка Олі | Список Тараса не містить нотатки Олі | ✅ Список містив лише власну нотатку Тараса |
| `GET /api/notes/:id` | Тарас звертається напряму до `id` нотатки Олі; і навпаки — Оля до `id` нотатки Тараса | 404 в обидва боки | ✅ `{"error":"not found"}`, HTTP 404 в обидва боки |
| `POST /api/notes` | Оля (заголовок `x-user-id: 1`) надсилає в тілі `"user_id": 2`, намагаючись створити нотатку від імені Тараса | Нотатка створюється під реальним викликачем (Оля), поле `user_id` з тіла ігнорується | ✅ Створено з `id`, без `user_id` у відповіді; у списку Тараса нотатка не з'явилась |
| `PATCH /api/notes/:id/archive` | Тарас перемикає архів нотатки Олі; і навпаки | 404 в обидва боки, стан нотатки не змінюється | ✅ `{"error":"not found"}`, HTTP 404 в обидва боки; після спроб нотатки лишились `archived: false` |
| `DELETE /api/notes/:id` | Тарас видаляє нотатку Олі; і навпаки | 404 в обидва боки, нотатка не видаляється | ✅ `{"error":"not found"}`, HTTP 404 в обидва боки; обидві нотатки підтверджено існували після спроб |

**Що знайшли:** Жодного пропуску, окрім уже засіяного й полагодженого в
Task C (`GET /api/notes/:id` без умови власника). Після фіксу всі п'ять
маршрутів, включно з власним ендпоінтом архівування, скопують дані виключно
через `WHERE ... AND user_id = ?` у самому запиті — жодного пост-фетч
патерну «дістали за id, тоді звірили власника в коді». `POST` додатково
підтвердив стійкість до mass assignment: ендпоінт взагалі не читає
`user_id` з тіла запиту, тож підмінити його неможливо в принципі, а не лише
завдяки валідації.
